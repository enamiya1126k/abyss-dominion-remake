# ABYSS DOMINION Build 531

Version 3.1.210 / ぬし釣り大騒動・種類と育成

## 適用

Build 530適用済みのゲーム本体に、このZIPの内容を同じ階層で上書きしてください。
`online-server` も同時に更新し、サーバーを再起動してください。その後、参加者全員が画面を再読み込みします。
セーブキーは変更していません。進行中の旧釣りデータは得点・竿の強さ・掛かっている魚を維持して移行します。
本ZIPは差分であり、単独起動用のゲーム本体ではありません。公開サイトへの反映は行っていません。

## 追加・変更

- 魚・生き物・アイテムを32種類から52種類へ。新規20種類に専用画像を追加。
- ルアーは６種類。月影スプーン／焔のスピナー／水晶ミノー／深淵ジグ／雷羽フェザーから、それぞれ専用の特別個体へ。
- ヌシ級はヌマオウ、コケガメ、ヨルナギ、アマツの４種類。毎試合25〜40秒に１匹が現れ、95秒より前に釣れば14秒後に別の１匹も登場。最大２匹、同時には１匹。
- ヌシ級は失敗しても消えず、約2.2秒休んで再挑戦可能。同じ個体の名前・重量を維持し、近くで待機中の浮きにも寄ってくる。独占予約と釣り上げ済み個体の二重獲得を防止。
- 通常の魚からも「エサにして続ける」が可能。次の魚は重量と希少度が上がる。最高ランク帯では大冠サイズに成長。連鎖は最大８回、得点補正は１回につき18％。
- 靴から宝箱の既存ルートは維持。ヌシの魚影を狙った場合は、ルートよりもヌシが優先される。
- 竿は最大Lv.８。釣り上げで成長＋１、エサ化で＋２〜３。得点化・失敗後も強化を保持する。対戦終了後はリセット。
- 巻いて回収・投げ直しを繰り返しても成長は増えない。連鎖エサがあるとき、別の在庫エサを誤消費しない。
- 手前は小魚、沖は大型・深海魚が多い。各エリアに全ての通常ランクの可能性を残した。専用ルアーの特別個体とヌシ級は別の出現ルール。
- 個体の基本重量を約0.55〜1.70倍で変動。大きいほど得点が上がるが、重量だけで得点が急増しない補正を使用。
- レア魚は暴れる周期・糸の張りで難しくし、取り込み時間だけで難易度を上げない。竿強化で張りへの耐性と巻き取りが改善。
- 育成ゲージとスクロール可能な52種類の図鑑を追加。
- Build 530の「手動投げ先指定」「投げる間だけエサ表示」「食いつく前の回収」「距離別の巻き取り」「魚影の接近・つつき」を維持。
- 釣り通信version 5。旧クライアントとの混在開始を拒否し、ブラウザ・サーバーの双方で同一ルールを使用。

## 検証

- 釣りのルール・通信・描画・操作・保存移行：80テスト通過。
- 直前ミニゲーム群（すごろく・胸毛・運動会・レース・ブロック等）の回帰：120テスト通過。
- 100シード×４席AIを完走。全席に勝利があり、得点・物理値・在庫数が有限、イベント保持上限を確認。
- Chromiumのモバイルエミュレーション（320×568、390×700、430×800）で手動投げ・ルアー連鎖・回収・得点化後の竿保持・ヌシ再挑戦・全52項目の図鑑スクロールを確認。
- `docs/build531/browser-results.json`、スクリーンショット、バランス比較を同梱。
- 入力遅延のない機械的な単独プレイ比較では、小魚の即得点化だけより、育成して沖・ヌシを狙う方が得点面で有利。これは実プレイヤーの勝率や端末性能を保証するものではありません。

### 検証環境の範囲

この作業環境は過去の差分を組み合わせたもので、元ゲームの一部キャラクター定義・表示モジュールがありません。通信／操作の検証では、その部分だけQA専用の代替定義を使用しています。釣りルール・UI・水面・魚画像・操作処理は本実装です。実機iPhone Safari、本番ネットワークでの複数人対戦、公開サイトへの適用は未確認です。

### 再実行

Node.js 24以上と `@napi-rs/canvas` が必要です。

```sh
node --test tests/build524-fishing.test.mjs tests/build525-fishing.test.mjs tests/build526-fishing.test.mjs tests/build530-fishing.test.mjs tests/build531-fishing.test.mjs
node tools/build529/regression.mjs
node tools/build531/balance.mjs
```

ブラウザ検証は `PLAYWRIGHT_MODULE`（playwright-coreのモジュールパス）、`CHROMIUM_PATH`、任意の `QA_FONT_DIR` を設定して `node tools/build531/browser-qa.mjs` で実行できます。
