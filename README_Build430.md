# Build430 / v3.1.109 — ⑥ オフライン挑戦・再同期

**Build429適用済みのゲームへ上書きする差し替え版である。** 共闘レイドに、取得済みの挑戦権を使ったオフライン戦闘と結果の再同期を追加した。

## 遊び方

1. サーバー接続中に「共闘レイド」を開く。
2. 「持ち出し挑戦権」から、1〜3回分の取得を選ぶ。先にオフライン用データを保存し、その後で挑戦権を取得する。
3. 「この挑戦権で遊ぶ」から、取得時の部隊で戦う。従来の手動・自動・速度変更を使用できる。
4. 操作記録は端末に保存される。途中でホームへ戻ったり再読み込みした場合は、「途中の挑戦を再開」から続ける。
5. 完了した結果は、接続時に自動送信される。受付確認が返るまでは端末に記録を残す。

挑戦権は**取得から24時間有効**である。戦闘を完了し、有効期限より前にサーバーへ結果を送信する必要がある。

起動用データは約12MBで、戦闘に使う画像も事前読込する。初回の取得はオンライン環境で行う。ブラウザーのサイトデータを削除すると、端末側の未送信記録も消えるため、送信が済むまでは削除しない。

## 回数と編成

| 項目 | 仕様 |
| --- | --- |
| 1日の枠 | オンライン挑戦＋取得する持ち出し挑戦権を合算して3回 |
| 消費時点 | オンラインは開始時、持ち出し挑戦権は取得時 |
| 日付 | サーバーの日本時間。0時に新しい日の枠になる |
| 日付をまたぐ権利 | 取得日の枠として消費済み。有効期限までは使用できる |
| 再送・再接続 | 追加の回数を消費しない |
| 中断・期限切れ | 取得した回数は返却しない |
| 編成・装備・魔法陣 | 挑戦権取得時の状態に固定する |

例えば前日に3回分取得し、翌日に新しく3回分取得した場合、前日分の有効期限までは両方を保持できる。取得日の枠を付け替えたり、翌日の枠から再度差し引いたりはしない。

持ち出し戦闘でも、最大10ラウンド・最初の5ラウンドはボス待機・Lv.100の取り巻きが行動する仕様を引き継ぐ。通常のオンライン挑戦中に通信が切れた場合は、従来どおり再接続後に再開する。

## 討伐後に届く結果と報酬

| 結果を受信した時点 | 処理 |
| --- | --- |
| 元のボスが生存中 | 再計算したダメージを順位へ加算し、残HPの範囲で共通HPを減らす |
| 元のボスが討伐済み・権利は有効 | 元のボスの順位へ加算する。次のボスのHPは減らさない |
| 有効期限に達した後 | 集計対象外として受付を終了する。確定順位・報酬を変更しない |
| 同じ結果を再送 | 保存済みの受付結果を返す。ダメージ・回数・報酬を再加算しない |

共通HPが0になると次のボスへ進む。その時点で有効な未送信の挑戦権が残っている場合は、前のボスの順位と報酬を「仮集計」とする。

**全結果を受領した時点、または残る挑戦権の有効期限で順位報酬を確定する。** 討伐後の待ち時間は最長24時間である。画面に仮集計と確定予定時刻を表示する。

「最後の一撃」は、サーバーの共通HPを最初に0にした攻撃または結果に確定する。後から届いた結果による変更はない。参加報酬・順位報酬・最後の一撃ボーナスの量と受取方法はBuild429を引き継ぐ。

順位には、各挑戦で再計算したボスへのダメージを計上する。討伐後の有効な結果も含むため、全員の累計ダメージがボスの最大HPを超える場合がある。共通HPを減らした量とは区別して記録する。

Build429までに確定・配布した報酬は変更しない。

## 保存と再同期

- サーバーが、所有者・対象ボス・編成・乱数・有効期限を記録した挑戦権を発行する。
- 端末は操作履歴を保存してから画面を進める。保存に失敗した操作は進めず、直前の保存済み状態を保持する。
- サーバーは同じ戦闘処理で操作履歴を再計算する。端末から送信されたダメージ値・HP・編成の上書きは採用しない。
- HP、順位への貢献、受付済み記録、討伐・次ボス移行、報酬確定を同じ保存処理で更新する。保存に失敗した場合はまとめて取り消す。
- 返信の紛失、再接続、同時送信、別端末からの再送でも、1枚の挑戦権を一度だけ反映する。
- 受信確認を端末へ保存できない場合も結果を残し、再送または挑戦権一覧から受付済み状態を復元する。
- 他人の挑戦権、存在しない挑戦権、未完了の戦闘、不正な操作記録は反映しない。

発行済み権利の再計算に使う戦闘処理は `src/worldRaid/runtime430/` に固定した。通常の第一章・第二章・既存オンライン戦闘の処理をそのまま利用し、それらのソースは変更していない。

## 導入

1. Build429のゲームフォルダへ、ZIP内の同名ファイルを上書きする。
2. **ゲーム公開側とオンラインサーバー側の両方を更新する。** サーバーの `online-server` と、隣にある `src` をセットで更新する。
3. 既存と同じ手順でNodeサーバーを再起動する。追加の依存パッケージは不要である。
4. ゲームをオンラインで再読み込みし、v3.1.109と「持ち出し挑戦権」の表示を確認する。

`world-raid-offline430-sw.js` と `world-raid-offline430-assets.json` も、ゲームのルートへ配置する。オフライン再読み込みは、HTTPSで公開したゲームとブラウザーのService Worker／Cache Storageを使用する。対応していない環境では、既に開いている画面内でのオフライン戦闘となる。

**既存の `data/world-raid.json` を削除・上書きしない。** `WORLD_RAID_STATE_FILE` を指定している場合は同じ保存先を使用する。挑戦権・受付記録も同じファイルへ保存する。ZIPに利用者のデータは含めていない。サーバーは引き続き単一Nodeプロセスで運用する。
