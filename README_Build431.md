# Build431 / v3.1.110 — ⑦ 全体確認・統合ZIP

**Build424以降の既存ゲームへ上書きする、①〜⑥の累積差し替え版です。**
Build425〜430を順番に入れ直す必要はありません。ゲーム本体とオンラインサーバーの更新ファイルを、元のフォルダ構成でまとめています。

元のゲーム一式・既存画像・サーバーの依存パッケージは、そのまま使用します。このZIPだけで新規設置する形式ではありません。

## 適用方法

1. ゲームのセーブと、サーバーの既存 `data` フォルダをバックアップします。
2. ZIPを展開し、`index.html` がある既存ゲームのルートへ、同名ファイルを上書きします。フォルダごと削除して置き換えないでください。
3. ゲーム公開側とサーバー側を両方更新します。サーバー側は `online-server/` と、その隣の `src/` をセットで反映します。
4. 既存と同じ起動設定・作業ディレクトリ・保存先でサーバーを再起動します。追加パッケージは不要です。
5. オンラインでゲームを再読み込みし、表示バージョンが **v3.1.110** になったことを確認します。

ルートの `world-raid-offline431-sw.js` と `world-raid-offline431-assets.json` も必須です。更新後は、オフライン起動用データをバックグラウンドで再準備します。新しい挑戦権の取得や、追加の回数消費は行いません。

**サーバーの `data/world-raid.json` を削除・上書きしないでください。** `WORLD_RAID_STATE_FILE` を設定している場合は、同じ保存先を使います。ボスHP・挑戦権・未確定順位・報酬・受付記録が入っています。ZIPに利用者のデータや環境設定は含めていません。

サーバーは引き続き単一Nodeプロセスで運用します。HTTPS公開とService Workerに対応したブラウザーで、事前保存済みのオフライン再読み込みが利用できます。未送信の結果がある間は、ブラウザーのサイトデータを削除しないでください。

## 統合内容

| 依頼 | 含まれる内容 |
| --- | --- |
| ① 母の表示・十律輪 | HP障壁の現在値／最大値、母の拡大、魔法陣の位置補正、背後の輪の拡大・回転・停止、停止後の結果表示 |
| ② 母の追加能力 | 被ダメージ時の召喚、1戦1回のふんばり、母が倒れた後に召喚敵が5ラウンド残った場合のHP30%復活（1回） |
| ③ ホーム・ショップ | 下部の装備管理、パーティーの調整中表示、左側の共闘レイド、旧ショップ14品の宝箱抽選 |
| ④ 共闘レイド | サーバー共通HP、1日3回、討伐後の次ボス、ボスの最初の5ラウンド待機、Lv.100の取り巻き |
| ⑤ ランキング・報酬 | ボス別累計順位・本人貢献、参加／順位／最後の一撃報酬、受取記録と重複防止 |
| ⑥ オフライン・再同期 | 取得済み挑戦権、戦闘途中の保存・再開、結果の再送、共通回数、討伐後の遅延集計 |

旧ショップ商品の抽選対象は第一章・第二章のソロ探索の宝箱です。ミミックは対象外です。既存の闇市場とオンライン探索の宝箱は従来仕様を引き継ぎます。

持ち出し挑戦権は取得から24時間有効で、その期限までの結果送信が必要です。討伐後に届いた有効な結果は元のボスの順位へ加算し、次のボスのHPは減らしません。残る権利の全件受付または期限切れで順位報酬を確定します。最後の一撃は、サーバー共通HPを最初に0にしたプレイヤーに固定します。

## 今回の通し確認で修正した点

- 挑戦権を受け取った直後、画面に古い残り回数が残る不具合を修正しました。
- 通信復帰・保存内容の更新時に、古い戦況がオンライン戦闘の画面へ戻る不具合を修正しました。
- 保存済み戦闘を再表示するとき、戦闘用の表示状態と攻撃対象も復元するようにしました。
- 古い状態通知や遅れて届いた挑戦権一覧で、最新の戦況を上書きしないようにしました。
- 更新時は新しいService Workerへの切替を待ってゲームを読み込み、更新版の起動データを再保存します。同じ公開元の別アプリのキャッシュ・登録は削除しません。

第一章・第二章の戦闘処理、母の能力、サーバーの報酬計算、発行済み挑戦権用の固定戦闘処理はBuild430から変更していません。セーブ形式も従来のschema 84を引き継ぎます。
