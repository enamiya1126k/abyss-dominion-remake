# Build560 · メインゲームのBGM再生・復帰修正

Build559 に重ねる本体更新。v3.1.239。オンラインサーバーの変更・再起動は不要。

## 調査で確認できたこと

2026-09-25 の公開リポジトリ `enamiya1126k/abyss-dominion-remake`、コミット `82a990b31cf6ed455502da3654b8ad805249086c` を参照した。

- 本体は v3.1.238。ホーム・探索・戦闘を含む７曲のMP3が実在し、検証用に取り出した音源もGitHub上のファイルと同じハッシュだった。
- 画面側の曲切替呼び出しは存在し、保存設定の初期値は音ON／BGM28%／SE45%。ユーザーの実際の保存設定は取得していない。
- 起動は `src/main.js` の１回限りの `pointerdown` で `audio.unlock()` を呼ぶ構成。
- 旧 `AudioSystem.unlock()` は、効果音用の `AudioContext.resume()` を待ってからBGMの `play()` を呼んでいた。効果音の復帰が保留されると、独立しているBGMも開始要求に到達しない。
- 最初の起動時に再生を拒否されるケースで、その後のタップに再試行処理がなく、無音のまま残ることを条件を制御したテストで再現。
- 曲ごとに別のHTMLAudioElementを作っていた。再生許可を要素ごとに扱う環境を模したテストでは、曲切替後の再生が拒否された。

通話表示があるスクリーンショットは中断の可能性を示すが、端末ログを採取していないため、その通話が今回の直接原因だったとは断定していない。OSが通話などを優先している最中の出音を強制する変更ではない。

## 修正

- タップ中にBGMの `play()` を直接呼び、効果音の `resume()` 完了待ちと分離。
- タッチ終了・ポインター解放・キー操作で再試行できるようにし、中断や初回失敗から復帰可能に。
- BGMプレーヤーを１つに統一し、同じプレーヤーの音源だけを切り替える。
- 同じ曲の再描画・音量変更・一時停止からの復帰では、先頭に巻き戻さない。
- 旧再生要求の遅い失敗が新しい曲を止めないようにし、重複再生要求をまとめる。
- 音OFF、音量0、非表示／画面離脱時の停止を維持。既存セーブやユーザーの音量設定は変更しない。
- メイン側の旧import URLも新しい音処理へ向くようにし、更新時のキャッシュを切り替える。

## 適用

1. Build559 適用済みのファイルへ、このZIPを同じ相対パスで上書きして本体を公開。
2. Safariで再読込し、設定画面の版が **v3.1.239** になったことを確認。
3. 「BGM・効果音」がONでBGM音量が0%でない状態で画面をタップ。
4. 通話が終了した状態で、ホーム→探索→戦闘の曲切替を確認。

ゲームデータの初期化は不要。MP3は変更していないため、このパッチには再同梱していない。公開サイト・リポジトリへ書き込む作業は行っていない。
