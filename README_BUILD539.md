# Build539 — 因縁の決戦！テトラポット渡り

バージョン：3.1.218。Build538を適用済みの本体・サーバー向け差分パッチ。

## 適用

1. 現在の本体、online-server、セーブ／サーバー状態ファイルをバックアップする。
2. ZIPを解凍し、同じ階層へ上書きする。`src`・`assets`・`index.html`・`online-server`・オフラインキャッシュ更新をすべて反映する。
3. online-serverを再起動する。本体も再読み込みし、参加者全員をBuild539へ揃える。
4. ホームの「パーティー」から「因縁の決戦！テトラポット渡り」を選ぶ。

このZIPは差分であり、空のフォルダーへ置くだけでは動作しない。所持キャラや既存セーブを置き換えるデータは含まない。

## ルール・操作

- 4人の同時レース。不足席はAI。既存の相棒選択とプレイヤーカラーを引き継ぐ。能力差はない。
- 4秒のカウントダウン後に開始。上方向がゴール。
- 海の画面で飛びたい方向を長押しし、離すとジャンプ。押したまま指を動かすと照準変更。最大パワーまで約1.15秒。
- 金色の着地点マーカーは着地可能、赤は落水予測。予測後に他の参加者が足場を動かす場合は着地条件も変化する。
- 下の長押しボタンでも現在の照準へ跳べる。左右の矢印で方向調整。枠外へのリリース、操作キャンセル、「ため解除」で取り消す。
- PCは左右矢印で照準、Space長押し／離すでジャンプ、Escapeでキャンセル。
- 毎回シードを変えた37足場のコース。3区間それぞれに7足場の安全ルートと4足場の近道がある。
- 着地すると傾く足場は滑り落ちる。回転足場は周回移動。沈む足場は初回着地から2.2秒で水没し、4.8秒で復帰する。
- 16秒ごとに大波。3秒前から予告し、3.2秒間は低い近道が水没する。白い足場と避難所は水没しない。
- 途中の2つの避難所を順番に通ってゴールへ。落水後は最後に到達した避難所へ約1.6秒で戻る。
- 最初のゴールから20秒、全員ゴール、または150秒のいずれかで終了。
- ゴールは到着時刻順。同一シミュレーション時刻のゴールは同順位。未ゴールは避難所到達数、最遠の着地点、落水の少なさの順。
- 落水時は、よりの「イージー！」演出。結果は表彰台と4人の記録を表示する。
- 「もう一度」「ミニゲーム一覧へ戻る」に対応。通信切断／ホーム滞在中はAIが引き継ぎ、復帰時には古いチャージを解除する。

## 画像・表示

内蔵imagegenで以下の3素材を生成した。PNG原稿のアルファを保持してWebPへ形式変換し、実際のゲーム描画で使用する。

- `assets/tetra539/pads.webp`：6種類の足場アトラス。
- `assets/tetra539/ocean.webp`：海面背景。
- `assets/tetra539/cover.webp`：ゲーム一覧・ロビー・結果のキービジュアル。

最終プロンプトは `docs/build539/art-prompts.json`。波、飛行軌道、水しぶき、ゲージはCanvas/CSSで動的描画する。実行中に画像生成や外部APIへの接続は行わない。

## 検証

- ルール9項目＋既存パーティーレース回帰5項目の合計14項目に合格。
- 100シードのコースで安全ルート・近道の各ジャンプが到達可能であることを確認。
- 実際に全安全ルートをジャンプし、チェックポイント更新、落水復帰、ゴールを検証。
- 5シードのAIレース、JSON保存後の同一結果、チャージ上限、短押し、不正入力、入力の再送、波、各足場、同着、ホスト／準備／更新版チェック、切断AI、再起動、再戦・一覧復帰を検証。
- Chromiumのスマホ相当3サイズ（320×568、390×844、430×932）で、実Canvasと本番WebSocket処理を動作確認。長押しとリリース、着地、マウス／タッチキャンセル、二度押し拡大防止、復帰、時間切れ、再戦、一覧、拡大制限解除を確認。
- 4つの実WebSocketクライアントから個別にジャンプ・ゴールし、全員の結果一致を確認。
- ブラウザー試験中のゲーム由来エラーは0件。詳細は `docs/build539/browser-results.json` と `rules-tests.txt`。

物理iPhone Safari上での検証は未実施。保管されている過去差分には元のキャラ描画・カタログ等の4モジュールがないため、ローカル試験時のみ `tools/build539/catalog-fixture.mjs` が代替する。スクリーンショット中の小さなキャラは検証用表示であり、実際の本体は既存のキャラ素材を使用する。代替モジュールを本番srcへ上書きしていない。`victory.png` はゴール付近へ置いた4人の接続試験であり、表示タイムは通常の全コース走破記録ではない。

テスト手順：Node.js 24で `node --import ./tools/build539/catalog-fixture.mjs --test tests/build539-tetra.test.mjs tests/build462-party-race.test.mjs`。ブラウザー試験は `tools/build539/browser-qa.mjs` を使用し、Playwright、Chromium実行ファイル、日本語フォントのパスを環境変数で指定する。テスト用HTTPサーバーは同スクリプトが子プロセスとして起動する。

## 実装

サーバーが50ms刻みで物理・チャージ・着地・順位を判定する。クライアントから任意の距離・到着位置・時刻を指定できない。表示フレームは100msごと。コースは初回／再接続時に渡し、通常フレームでは差し替えない。新規プロトコルは `tetraVersion539:1`。既存ゲームの進行ルールには変更を加えていない。
