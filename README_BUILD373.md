# Build373 / v3.1.53 — Safari共有時のエラー画面対策

Build372適用済みのゲームフォルダーに上書きする差分ZIPです。Web側の配信後に一度再読み込みしてください。サーバー再起動は不要です。

## 修正内容
これまではwindowのerrorイベントを受け取ると、起動後であってもゲーム全体のDOMをエラー画面に置き換えていました。
ゲーム本体のimport完了後に限り、以下をすべて満たす通知ではゲーム画面を保持します。
- メッセージがScript error.またはScript error
- エラーオブジェクトがない
- 発生ファイル名がない
- 行番号・列番号がない／0

通知はコンソールとメモリー上の直近20件の記録に残します。保存データ・通信・戦闘処理には変更を加えていません。
起動前のエラー、具体的なファイル名や行番号があるエラー、通常のTypeError、Promiseの未処理拒否は引き続き表示します。エラー本文はHTMLとして実行されないようエスケープしています。
Build372のタイトル入りスライムアイコン指定も維持します。

## 検証
回帰テスト5件成功：起動後の発生元不明通知でもDOMを維持、診断件数の上限、起動失敗の表示維持、具体的エラー／Promise拒否の表示維持、本文のエスケープ、import完了後の起動判定を確認。
変更JavaScriptの構文と差分ZIPを確認。
iPhone実機のSafari共有シート操作は未検証です。共有操作に伴う元の通知そのものの発生原因は特定しておらず、今回修正したのは情報のない通知でゲーム画面を破壊してしまうアプリ側の処理です。

## 確認方法
配信後、一度ゲームを再読み込みしてv3.1.53になったことを確認し、Safariの共有を開いて閉じてください。ゲーム画面が残り操作できるか確認してください。引き続きエラーになる場合は表示されたエラー全文を確認する必要があります。
ホームアイコンやWebサイトデータの削除は不要です。

参考：Window error event — https://developer.mozilla.org/en-US/docs/Web/API/Window/error_event
