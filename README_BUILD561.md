# ABYSS DOMINION Build561 / v3.1.240

Build560でBGMが直らなかった件の追加修正です。Build560へ上書きしてください。本体のみの更新で、サーバーの再起動は不要です。

## 今回特定した不具合

公開サイトのindex.htmlとService WorkerがBuild560に更新されていることを確認しました。音源自体も正常で、ホーム曲への `Range: bytes=0-1` に対して公開サーバーは正常な206応答と2バイトを返しています。

ところが旧Service Workerは、その206応答を `Cache.put()` へ渡していました。部分応答は保存できないため例外になり、ブラウザーの音楽プレイヤーへ音源が届きません。また、音源が既にキャッシュされていると、2バイトの要求に曲全体を200応答で返していました。

旧コードを実ブラウザーで動かし、未キャッシュ時の取得失敗、キャッシュ済み時の不正な範囲応答、実音源の再生時間0・MediaErrorを再現しました。Build560の再生確認はService Workerを通しておらず、この配信経路を検証から漏らしていました。

## 変更内容

- 音源・映像・Range付きの通信をService Workerの共通キャッシュから外し、ブラウザー標準の通信に任せます。HTTPキャッシュはブラウザーが管理します。音源のオフライン再生は保証しません。
- キャッシュへの保存に失敗しても、正常に取得した画面やコードの応答は返します。画像・コードのオフラインキャッシュは維持します。
- 音源の読み込みエラー後は、次のタップで読み直して再生できます。
- 設定のBGM音量の下に、再生状態と「BGMを再生し直す」ボタンを追加しました。OFFや音量0%を勝手に変更しません。
- 音源7曲、効果音の内容、サーバー、ゲームのルール、セーブデータは変更していません。

## 更新後の確認

1. ZIPを展開し、フォルダー階層を保ってBuild560に上書きし、通常どおり公開してください。
2. Safariでページを再読み込みし、バージョンが **v3.1.240** になったことを確認してください。新しいキャッシュ処理へ切り替わります。
3. ホームなどで一度タップしてください。まだ無音なら、設定でBGMがON・音量が0%より大きいことを確認し、「BGMを再生し直す」を押してください。
4. 解消しない場合は、設定に表示される再生状態とv3.1.240の表示がわかるスクリーンショットで切り分けられます。

ゲームデータの初期化やSafari全体の履歴削除は不要です。このZIPを作成した時点では、こちらから公開サイトへ書き込み・反映は行っていません。

## 検証と限界

実際のService Worker、実音源、Cache APIを使い、旧版の失敗から新しいWorkerへの切替、同一キャッシュに古い音源が残る状態、全7曲のPCM出力、通信エラーからの再試行、OFF・0%維持、画面復帰を確認しました。コードのオフライン取得も確認しています。音声ライフサイクルと回復処理の12テストが通っています。

検証ブラウザーはChromium 133です。iPhone実機のSafariや通話中の音声出力は未確認であり、報告端末のログを直接取得したわけではありません。端末側の消音・通話・出力先についてはこのテストで保証しません。

再現結果は `docs/build561/browser.json`、検証手順は `docs/build561/QA.md` にあります。
