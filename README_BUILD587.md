# Build587 / v3.1.266 — とびだせ！魔界ランナーズ

Build586 に上書きする差分です。前回の Build586 適用済みの本体と online-server を対象にしています。

## 適用

1. ZIP を展開し、中身をプロジェクトのルートへ同じフォルダ構成で上書きしてください。`src` と `online-server/src` の両方が必要です。
2. 本体の配信ファイルを更新し、online-server を再起動してください。依存パッケージの追加はありません。
3. 参加者全員がページを再読み込みし、v3.1.266 / Build587 を使ってください。旧版のクライアントは新作の準備・開始を受け付けません。
4. パーティー一覧の先頭に「とびだせ！魔界ランナーズ」が追加されます。相棒を選んで準備OK、部屋主が開始します。空席はAIです。

既存のデータや環境設定を置き換えるファイルは入っていません。差分のみのため、空のフォルダへの展開では動きません。GitHub への push・公開サイトへのデプロイは行っていません。

## 遊び方

- ４人で同じ横スクロールコースを走るレース。制限時間は75秒。最初のゴールから残り16秒になります。
- 左下の◀▶を押したまま移動。右下のジャンプは短押しで低く、長押しで高く飛びます。移動とジャンプは２本指で同時に押せます。
- PC は ←→／A・D で移動、スペース／↑／W でジャンプ。
- 甲虫は上から踏むと倒してバウンド。倒した敵は約4.8秒後に戻ります。横から接触するとミスです。
- バネで大ジャンプ。緑の宝石で2.6秒の加速。宝石の取得状況はプレイヤーごとに独立しています。
- 森、浮遊遺跡、魔王城への道の３区間。浮遊足場を使う上のルートもあります。
- ハートは３つ。落下・敵への接触で１つ失い、最後に越えた旗から再開します。旗でハートは増えません。復帰直後の1.2秒は敵の接触から保護されますが、穴は危険です。
- ハートがなくなるとそのレースは脱落。顔を押して観戦相手を切り替えられます。ゴール後も残りの仲間を観戦できます。
- 点数制ではありません。ゴールしたタイム順、未ゴールなら最も進んだ距離で順位が決まります。同着・同距離は同順位。
- 相棒の能力差、プレイヤー同士の衝突はありません。離席・切断中は同じ物理ルールのAIが操作を引き継ぎます。

## 操作と同期

40Hz のサーバー判定と50ms間隔の状態配信。加速・減速、移動足場への追従、可変ジャンプは本体とサーバーで共通の物理処理を使います。足場から離れた100ms以内のジャンプと着地直前125msの入力を補助します。空中での連打による追加ジャンプはできません。

指を離す・タッチ取消・画面外への切り替えで操作を解除します。入力更新が350ms途切れた場合にも停止します。サーバー再起動で長時間空いた場合、試合の時計と敵の復帰・加速・再スタート時刻をまとめてずらし、勝手にタイムアウトさせません。

## 検証

- 新作の物理・ルール、４人の実 WebSocket 通信、旧版ゲート、所有相棒の選択、再接続、観戦、再戦、キャッシュ更新を確認。
- 共有サーバー経路の既存ゲーム回帰テストも含め、`docs/build587/tests.txt` に結果を記録。
- Chromium のタッチ端末エミュレーションで320×568、390×844、844×390を確認。既存の全292スタイルシートを読み込み、２本指操作、停止、左右移動、キャンセル、効果音、キーボード、表示のはみ出し、観戦と再戦を確認。
- iPhone 実機・Safari 実機は未検証です。

リポジトリ内の再現用チェックは `python3 tools/build587/verify.py`。ブラウザ検証は Playwright と Chromium がある環境で `node tools/build587/browser.mjs`。差分ZIPには実行に必要な更新ファイルとこの説明を収録しています。

## 画像

新しい専用背景 `assets/runners587/background.webp` と表紙 `assets/runners587/cover.webp` は組み込み image_gen で生成したオリジナル画像です。最終プロンプトと生成方法は `assets/runners587/SOURCES.json` に収録。元のPNGからWebPへ変換しています。既存の相棒画像を再利用し、足場・敵・バネ・宝石・ゴールはゲーム内の描画コードで表示しています。
