# Build566 検証記録

## 対象と結果

- 本番のRules566、CraneCoordinator566、PartyCoordinator462、RaceCoordinator451を使用。古いゲームも同じ調整役へ接続するため、ホッケー・爆弾・かくれんぼ・テトラの通信回帰とカート回帰も実行した。
- 79テスト成功、失敗０。`tests.tap` に全結果を保存。
- 64シードのAI対戦：全試合終了、横取り2,496回、ミミック事故445回、宝の獲得3,881個。勝者の席の内訳は15／11／22／17（同率１位を含む）。これは自動試合の結果であり、面白さや対人難易度の実測ではない。
- 得点前の横取り、再横取りに対応する所有権、得点二重計上の防止、同時接触、移動する当たり判定、進路の最初の宝、減点の下限、発射間隔を検証。
- 同じ宝への同時接触は衝突時刻を優先し、完全同時ならシミュレーションの時刻で席の優先を巡回する。固定された席から処理した人が常に勝つ方式を避けた。
- 90秒以降の発射を拒否し、発射済みのクレーンの回収後に結果へ進む。猶予は最大10秒。同点の順位と勝者を検証。
- ３人人間＋１人AI、４人人間、全AIの構成、所持相棒の確認、部屋主権限、旧版拒否、離席・切断時のAI、復帰、JSON保存復元、再戦、一覧復帰を確認。
- ４本の独立したWebSocketを通して、本番のRaceCoordinator451.handle、入力検証、シミュレーション、個別フレーム送信を通過。外側のログイン認証ハンドシェイクはこの試験の対象外。
- GitHub Pages／公開サーバーへのデプロイと、実機iPhone/Safariおよび実際の４人試遊は実施していない。

## ブラウザー

Chromium 153.0.8010.0。`chromium-browser.json` が機械可読記録。390×740、320×568、740×390で４席ずつ確認した。盤面は390×740で約502px、320×568で約382px、横画面で350pxの高さ。自分の席が常に下に来ること、盤面・操作欄に横はみ出しがないことを確認。

ネイティブのCDPタッチで発射・二重発射防止・キャンセル・90度回転した席からの発射を検証。キーボード操作、実際の横取りによる＋12点、ミミックによる−4点、相棒選択、結果画面、再戦ボタンの部屋主制限、接続切れ表示、旧ルール更新案内、動きを減らす設定を確認。JavaScriptエラー０、画像等のHTTP失敗０。

本番のクレーンView/Board/Rulesと素材を使用。外側のPartyView内の参加者一覧は表示試験でのみ隔離し、パーティーの権限・参加・準備は本番サーバーを用いた別試験で検証している。全RPGをブラウザーで起動したE2E試験ではない。

`snatch-demo.gif` は表示確認用に宝の位置を設定した後、本番のタッチ入力・移動・横取り・得点を実行した13秒の記録。前半は大宝箱の横取り、後半はミミックを奪って噛まれる展開。
