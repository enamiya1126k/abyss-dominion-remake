# Build420 統合確認

## 構成

基準はBuild416（①適用前）。Build417・418・419の修正をすべて引き継ぎ、Build420 / v3.1.99としてまとめた。統合対象は12個のゲーム本体ファイルである。`runtime-manifest.json` は基準と納品ファイルのSHA-256、`runtime.diff` はBuild416との差分を記録する。

Build419からの処理追加・バランス変更はない。今回のゲーム本体差分は `index.html` のキャッシュ識別・config参照と `src/core/config.js` のバージョンのみである。

## 実行ファイル

- `regression.txt`：Build420作業版の全256件の結果。
- `staged-regression.txt`：Build416へ納品ZIPを上書きした状態の全256件の結果。
- `display-structure.json`：実画面HTMLの構造確認5条件。
- `package-validation.json`：Build416〜419への上書き後の本体一致とZIP整合性。
- `tests/build420-expedition-integration.test.mjs`：今回追加した階層移動・保存再開・再入場3件。

テストは本体main.jsの関数をASTで抽出し、SHA-256が一致するソースで実行する。DOM、音声、演出の待ち時間などは模擬する。階層移動では迷路生成・Entity移動・出口処理、保存再開では実際のSaveServiceと復元関数を使用する。描画結果はブラウザーのピクセル検証ではない。

## ZIP適用

Build416のコピーに統合ZIPを展開して全テストを実行する。Build416・417・418・419の各構成に対して、ZIPで置き換わるファイルと残るファイルの双方を比較し、上書き後の `index.html` と `src` 全体がBuild420と一致することを確認する。

セーブキー・schema 84は変更なし。画像・音楽、報酬定義、キャラクターとペアの能力定義、オンラインサーバーは変更なし。HP補正の倍率は変更しない。

## 未確認の範囲

control-browserで確認用URLを開いたが、`net::ERR_BLOCKED_BY_CLIENT` により表示できなかった。ブラウザー制限の回避は行っていない。iPhone Safari実機の描画、実際のタップ、端末ごとのFPS、本番サーバーとの同時接続は未確認である。

負荷については泉で静止中に回復・保存を繰り返さないこと、再配置や説明表示が状態を増やさないことを確認した。端末上の性能測定とは区別する。
