# Build431 統合確認記録

## 対象

Build430を元に、表示復帰と更新キャッシュを修正。①〜⑥の変更はBuild424との差分として統合した。
本番へのデプロイや利用者のセーブ書換えは実施していない。

## 発見・修正した表示復帰の問題

Build430の画面層は、最新のオンライン戦況とは別に、保存負荷を抑えるためのキャッシュを持っていた。
オフライン機能から画面更新通知が来ると、その古いキャッシュを直接画面へ戻す場合があった。また、キャッシュから戻したときは通常の戦闘表示の初期化を通っていなかった。

修正後は、サーバーの更新番号・時刻で新旧を判定し、最新戦況を保持する。画面の復帰も共通の戦闘表示更新を通す。遅れて届いた挑戦権一覧は権利の受付処理を行いつつ、戦況を巻き戻さない。

再現テスト5件は修正前に全件失敗し、修正後に全件成功した。修正前の再現ログは `regressions-before.log` に残した。

## 連続操作テスト

1. 第一章の宝箱を開け、SaveServiceで保存・再読込。再開封でアイテムが増えないことを確認。
2. オンライン挑戦を1回使用し、持ち出し権を2回分取得。残り0回を確認。
3. 切断状態で持ち出し戦闘を途中まで進め、セーブを読み直して再開。2戦分の結果を未送信で保存。
4. 別プレイヤーが元のボスを討伐。次ボスへ移行するが、前ボスの報酬は仮集計で待機。
5. 再接続後、保存した結果を送信。最初の返信を破棄し再送しても1回分だけ加算。
6. 2件目を受領すると旧ボスの順位・報酬を確定。次ボスHPは減らず、最後の一撃も変更されない。
7. 報酬受取のローカル保存を故意に失敗させる。通貨・受取記録を戻し、サーバーへのACKを送らない。
8. 保存を復旧して受取。再読込・再配信でも増額は1回。サーバーも再起動して受付済み・受取済みを保持。
9. 最初の宝箱の取得記録、未送信結果の受付済み記録、残り回数が維持されていることを確認。

## 検証上の限界

本番接続・実WebSocket通信・実機の画面描画は未実施。配布元の全画像は作業フォルダに存在しないため、実画像を読み込んだiPhoneでの表示確認を代替したものではない。
ZIPは既存ゲームへ重ねる差し替えファイルとして構成し、元の画像や既存依存パッケージを残す。

母の54戦の編成確認、共闘レイドの12戦の固定乱数比較はそれぞれBuild426・430の既存記録を同梱している。今回は戦闘ロジックと固定runtimeの同一性を確認し、全件回帰テストを実行した。過去の編成試験を今回新たに実施したとは扱っていない。
