node --test --test-reporter=tap tests/build561-audio-recovery.test.mjs tests/build562-luck-items.test.mjs tests/build562-luck-wire.test.mjs tests/build563-rules.test.mjs tests/build563-wire.test.mjs

結果は **142件成功、失敗・スキップ０**。`tests.tap` に記録した。Node.jsのテストランナーを使用し、通信テストには `ws` またはPlaywrightに付属するWebSocket実装が必要。

| 分類 | 件数 | 主な確認 |

| Build561音声 | 2 | 読み込み失敗・再試行、OFFと音量０の尊重 |

ピンボールは20シードの90／150秒試合で物理状態、得点、最大速度時の境界を確認。爆弾は30シードの全３回を進行し、１試合の全員合計18点と各席の勝利例を確認。テトラは20コースの到達経路と、正当な着地の前に波で失敗しないことを検証した。かくれんぼは脱出・時間切れ・調査条件に加え、鬼に見えない逃走者の座標・家具の持ち主が公開されないことを確認した。

４人通信はローカルの４つの独立したWebSocketクライアントから、実際のPartyCoordinatorと各ゲームCoordinatorに要求を送る構成。認証・インターネット回線・公開サーバーへの配置はこのテストには含まない。

## ブラウザー

```sh
node tools/build563/browser.mjs
```

PlaywrightとChromiumを用意して実行する。システムChromiumを使う場合は `QA_CHROMIUM` に実行ファイルの絶対パスを、検証と同じ日本語フォントを使う場合は `QA_FONT` にNoto Sans JPのフォントファイルを指定できる。未指定時はPlaywrightのChromiumとシステムフォントを使う。

確認結果は `browser.json`、画面は同じフォルダーの `*-mobile.png` と `*-result.png` に記録。390×740、320×568、740×390で４ゲームとも横にはみ出さず、盤面が画面内に収まった。JavaScriptエラー０、リソース取得失敗０。

実際のView、CSS、画像、ゲーム計算を使用し、パーティー・キャラクター一覧は独立した検証用データに置き換えた。タッチの発射・キャンセル、爆弾の１回だけの受け渡し、受け取り直後の操作制限、足場タップ、封印への道案内、別目標の選択、追加操作、家具への接近と調査、４ゲームの待機室・結果画面を確認した。

今回のブラウザーはChromiumであり、iPhone実機Safariでの検証ではない。対人での面白さ・熟練度による難易度差は自動テストから断定しない。

## 維持した部分

`preserved.json` に44ファイルのSHA-256を保存。カート・ゴリラ・運動会のゲーム本体と音声復旧の３ファイルがBuild562と同一であることを確認した。共有パーティー処理と通信バージョンは新ルールに対応して更新した。

音声・Range要求をキャッシュから除外するService Workerの処理は維持し、キャッシュ名のみBuild563へ変更。新しいモジュール、スタイル、旧importmap別名、オフライン資産一覧を配布チェックで照合する。

配布物は既存Build560～562への累積差分。既存の公開済み画像を再利用し、保存データと秘密情報を配布に含めない。`BUILD563_MANIFEST.json` に同梱ファイルのサイズとSHA-256を記録する。
