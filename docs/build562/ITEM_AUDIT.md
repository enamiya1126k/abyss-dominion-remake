# 運だけ大運動会・全40アイテム検証（Build562）

対象：Build560の公開リポジトリーの運動会処理（Build561時点でも同一）。継続装備28種、1回だけの選択12種。そのうち大技は11種で、ワープゲートは大技に含みません。

## 判明した不一致

|箇所|旧処理|修正後|
|---|---|---|
|お守りバルーン|残数と装備数の大きい方に戻す|残数＋装備数。残り3・装備1なら4|
|余韻アンプ|各50%分を先に切り捨てる|合算と倍率の後で切り捨て。321m・2個なら321m|
|横取りレンチ|回の開始時の装備で狙い続ける|その攻撃時点で奪える装備から狙い直す|
|装備表示|攻撃完了後の防御・資源・装備を先に表示|一斉公開、攻撃到達、反射到達の時刻に合わせる|
|成長倍率表示|一部の場面で次の回の倍率を表示|表示中の回に適用される倍率|

## 共通処理

- 装備は「次の回から」とある効果を除き、選んだ回から発動。補充と加速の計算後に、ランダムな順で攻撃し、最後に移動する。
- 同じ種類の攻撃装備は威力をまとめて1発。異なる種類は別の攻撃。攻撃1発を防ぐと防御を1回消費する。
- 防御の優先順は、対応するスプリング→バリア→反射ミラー→お守り。防いだ攻撃では逆境バッテリーは充電されない。
- 大技を選ぶと貯金・太陽・コイルを消費する。出目で外れたり、後から攻撃で止められても戻らない。装備そのものは残る。
- 距離は1m単位。前進の倍率は全部掛けてから端数を切り捨てる。後退には倍率を掛けず、累積距離は0m未満にならない。

残数表示はサーバーが確定した事前状態と攻撃ログから描画し、画面表示のためにゲーム状態を書き換えません。横取りされた装備も到達時刻に合わせて表示します。旧形式で一斉公開済みの結果は再計算せず保存済みの結果を維持します。

## 検証方法・範囲

- `tests/build562-luck-items.test.mjs`：説明から記述した期待値で109テスト。全40種、継続28種の重複、混合倍率、攻撃順、防御優先順位、反射、資源の全消費、持ち越し、端数、巨大整数、表示時刻を確認。サイコロ4種×バフ7条件×出目216組＝6,048条件も含む。
- `tests/build562-luck-wire.test.mjs`：実サーバーハンドラーで4テスト。旧バージョン混在、開始権限、非公開の手札、重複選択、8/16回戦、途中のJSON保存・復元、確定処理の重複を確認。公開WebSocketへの接続試験ではありません。
- `docs/build562/reproduction.json`：旧計算と新計算を同じ入力で比較した数値。
- `docs/build562/browser.json`：実際の運動会描画・CSS・アイテム画像を読み込み、390px/320pxのタッチ画面で操作と残数を検証。日本語フォント付きで表示確認。パーティー待機室・肖像のみ検証用の代替を使用。iPhone実機は未確認。
- 画像素材・倍率上限・他のミニゲーム・セーブ形式は変更なし。Build561のBGM修正を維持。
