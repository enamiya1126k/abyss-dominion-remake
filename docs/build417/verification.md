# Build417 検証記録

## 基準と変更範囲

基準は直前に配布したBuild416（v3.1.95）である。実行ファイルの変更は `index.html`、`src/main.js`、`src/services/SaveService.js`、`src/core/config.js` の4点である。セーブキーとスキーマ84を維持する。

## 再現した不具合

Build416の関数を実行し、次の6ケースで不具合を再現した。`before.txt` に修正前の失敗を記録した。

1. 100階で敗北後、区画表示を折り畳む予約コールバックが実行されると、取り除いた戦闘画面が再生成される。
2. 敗北結果を表示中に途中保存を呼ぶと、削除した `activeBattle` が再作成される。
3. `inRun=false` の終了済み探索に通常戦闘が残った旧セーブを読み込んでも、戦闘データが除去されない。
4. 同じ終了済み探索の戦闘を、復帰処理が受け入れてしまう。
5. 探索終了状態でも遭遇演出を開始し、終了判定で中断した際に遭遇フラグと停止状態が残る。
6. 遭遇演出の世代が変わって中断した際も同様に停止状態が残る。

敗北処理は味方をHP1・MP0へ救出し、現在階をチェックポイントへ変更する。結果表示中は戦闘オブジェクトが残る一方、通常の敗北では `resultSettled=true` になる。旧描画・途中保存がこのフラグを確認していなかったことが、再表示と再保存を許す原因である。

ユーザーの「敵行動中に停止」「全員HP1・MP0」「1階表示」「再入場で復旧」と整合する経路を再現した。実端末のログと実セーブは取得していないため、個々の発生時刻のイベント順序まで断定するものではない。

## 修正後の検証

既存224件と新規13件、合計237件を実行する。新規テストは描画予約・ページ離脱保存・旧セーブ復帰・遭遇中断・再入場・終了後の行動処理を対象にする。

- 100階のHP1・MP0で、通常遭遇が開始され、途中セーブの階も100に保たれる。
- HP1・MP0・毒の状態から、敵行動・ラウンド処理・敗北結果・拠点復帰が進む。
- 報告された敵4種と味方4人（ひで・カルミア・セリア・アルテア）を使い、10通りの乱数条件で本体の敵AIと戦闘処理を実行する。瀕死の味方が敗北した後、遅延描画と途中保存を呼んでも戦闘が復活しない。装備や乱数を含む利用者の実セーブの完全再現ではない。
- 終了した通常探索の残存戦闘だけを除去する。記憶戦・第二章・4対4・勇者遭遇の特殊戦闘は、通常探索の外でも保存データを維持する。
- 遭遇キャンセルは自分が所有する停止状態だけを解除する。新しい遭遇や開いているダイアログに干渉しない。
- 第一章・第二章・手動試練のHP、MP、状態異常、行動位置の保存復帰を回帰確認する。
- 既存の報酬二重取得防止、手動スキル選択・連打、自動から手動への切替を回帰確認する。
- 深淵・十神の68通りの基準能力・スキル構成を維持する。

## 検証方法と限界

Node.jsのテスト環境で、本体 `main.js` の関数をASTで抽出して実行した。ハーネスは本体のSHA-256を照合し、別バージョンのコードを誤って検証しない。画面部品、音声、待ち時間は模擬し、描画関数の再呼び出しと保存・戦闘・遭遇処理を検証した。

ブラウザーの実際のレイアウト、iPhone Safariのタッチ操作、通信中の本番マルチプレイは未検証である。オンラインサーバー、能力データ、ダメージ倍率の実装ファイルはBuild416から変更していない。

同梱された `tests`、`tools/build417`、既存ゲーム全体がある状態で `node --test tests/*.test.mjs` を実行して再検証できる。
