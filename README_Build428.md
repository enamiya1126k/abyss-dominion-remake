# Build428 / v3.1.107 — ④ 共闘レイドの土台・戦闘

Build427 適用済みのゲームに上書きする差し替え版です。左側の「共闘レイド」から参加できます。

## 今回の仕様

- サーバー全員で一体の共通HPを削ります。各プレイヤーは自分の部隊4体で、既存の手動・自動戦闘を使います。
- 1人1日3回。日本時間0時に回復します。挑戦開始時に1回消費し、中断・敗北でも返却しません。ボス討伐による回数の回復はありません。
- 1回の挑戦は最大10ラウンド。第1〜5ラウンドはボスが攻撃せず、第6ラウンドから攻撃します。Lv.100の取り巻き2体は第1ラウンドから行動します。
- 共通HPは初期1000億。討伐時だけ既存レイド3種を順番に切り替えます（1000億→1200億→1400億→次の周回）。日付・週替わりによる切り替えはありません。
- 結果画面に今回のダメージ、受付に現在のボスへの累積ダメージを表示します。取り巻きへのダメージは共通HPへの貢献に含めません。
- 巨体耐性：このボスだけ、割合攻撃・継続ダメージはHP160万を上限に計算します。即死は最大40万ダメージへ変換します。通常攻撃は従来の計算です。取り巻き・既存レイド・第一章・第二章の計算は変えません。

## 導入

1. ZIPを展開し、ゲームのルートへ同じフォルダ構成で上書きします。`src` と `online-server` の両方が必要です。
2. 稼働中のオンラインサーバーを停止して、そのサーバーのゲームフォルダにも今回の差分を反映します。`online-server` だけを別の場所へコピーせず、隣の `src` も更新してください。既存と同じ起動手順でNodeサーバーを再起動します。
3. ゲーム画面を再読み込みし、v3.1.107と左側の「共闘レイド」を確認します。サーバーを更新していない場合は「開催準備中」と表示されます。

既存のセーブ・設定・サーバーデータを削除する操作はありません。既存サーバーの依存パッケージをそのまま使用し、追加のインストールはありません。

共通HP・挑戦回数・各挑戦の進行・討伐貢献・最後の攻撃者は、サーバーの作業ディレクトリの `data/world-raid.json` に保存します。保存先は `WORLD_RAID_STATE_FILE` 環境変数で指定できます。**このファイルを更新時に削除・上書きしないでください。** ZIPには利用者のデータファイルを含めていません。既存サーバーと同様、単一のNodeサーバープロセスで運用する構成です。

## 通信と保存

- ダメージはサーバーが計算します。クライアントから送ったHPやダメージ値は受け付けません。
- 挑戦開始の受付IDを保存するため、連打・返信紛失・再送で二重に回数を消費しません。
- 切断中は進行を一時停止し、再接続で同じ挑戦を再開します。保存済みの進行はサーバー再起動後も復元します。
- 同時に討伐した場合も残HPだけを計上し、次のボスへの切り替えを一度だけ行います。旧ボスへの挑戦は全員分を終了します。
- データ保存に失敗した操作は、HP・回数・ボス移行をまとめて取り消します。破損データがある場合は勝手に初期化せず受付を停止します。

今回の範囲はオンライン戦闘の土台です。**ダメージランキング画面、順位報酬・最後の一撃の報酬配布、オフラインでの新規挑戦と後日の反映は、次の工程です。** そのため、今回の共闘レイドから報酬はまだ配布しません。貢献と最後の攻撃者の記録は残します。

## 確認結果

- 自動テスト361件成功。従来機能337件に、新規24件を追加。
- 複数プレイヤーの共通HP加算、3回制限、日本時間の日付境界、同時討伐、再送、切断・再接続、保存障害、保存ファイルからの復元を確認。
- 既存のサーバー通信振り分け処理を、メモリ内の模擬ソケットで実行し、認証・バックグラウンド接続・共闘中の部屋移動禁止を確認。
- 4編成×乱数3種の計12戦を既存の自動戦闘で確認。すべて10ラウンドで終了。Lv.10000・装備なしの条件で、ボスへのダメージは約46万〜454万でした。
- Build427へZIPを上書きした別フォルダでも自動テストを実行。

実サーバーへの配信、実際のWebSocket通信、iPhone Safariでの表示・操作確認はこの環境では実施していません。配信後は「2端末で共通HPが一致する」「残り回数が再読み込み後も一致する」「6ラウンド目からボスが動く」を確認してください。
