# Build615 — マルチプレイの参加者側のカクつきを改善

Build614適用済み本体へ上書きする修正パッチ。アプリ3.1.294。
サーバーはBuild613と互換。今回のサーバー更新・再起動は不要。

## 修正

- ミニゲーム共通の表示時刻を、端末の単調時計で進める方式に変更する。各受信パケットの到着間隔に引っ張られて時刻が巻き戻ることを防ぐ。既存ゲームの `Date.now() + offset` も同じ時計につなぐ。時計合わせには既存サーバーの時刻応答を利用する。
- ランナーズの自分の移動予測を補正する際、新たな補正量をその瞬間に減衰させていた処理を修正する。遅延で大きくなった誤差を数フレームに分けて吸収し、方向転換やジャンプの操作は引き続き即座に予測へ反映する。描画位置をコース左右の外へ出さない。
- ランナーズと壁よけの他プレイヤー、エレベーターのキャラクターと落下物を、受信時刻ではなくサーバー上の時系列で補間する。まとめてデータが届いても途中の位置から描画を再開する。データが途切れた場合は最後の位置で待つ。ランナーズの移動する足場と乗員の位置合わせは維持する。
- 壁よけでは自分の移動予測にも段階的な補正を加える。
- 通常の状態取得が新しいリアルタイム位置を古い状態へ戻さないようにする。報酬受取、退出、ゲーム切り替えは通常の応答で処理する。
- 新しい読み込み先とBuild615用キャッシュに切り替える。通信ルールは23のままで、Build614のゲーム選択画面の修正も維持する。

勝敗・当たり判定は引き続きサーバー側の計算に従う。船、スター、敵、ボス、コースのルールは変更していない。

## 適用

1. Build614適用済み本体へ、ZIP内のファイルを同じ位置に上書きする。
2. 本体を公開している場所へ反映する。
3. **参加者全員が再読み込みする。** ホストだけを更新しても、他の端末の描画処理は更新されない。

Build613のサーバーへ更新済みであれば、サーバー側の作業は不要。このZIPにはサーバーの変更を含まない。
公開サイトへの反映はこの作業では実施していない。

## 検証

284件のテストが通過した。

- 2人構成と4人構成で、実際のランナーズの入力・物理計算を使用した遅延再現テストを実施した。参加者側の上り125ms、下り110msに最大100msの揺れを追加した条件を含む。WebSocketの順序を保ったまま、受信がまとめて発生する状況を再現した。
- 修正前の実ファイルと比較し、同条件の60Hz描画で最大のフレーム間移動が32.39から15.06ワールドピクセルに減った。ホスト側の同テストは15.06。ジャンプの入力が反映され、入力を離した後はサーバーの位置へ収束することも確認した。この値は特定のテスト経路での結果であり、実機のFPS測定ではない。
- 本番の共通受信処理と、ランナーズ・壁よけ・寿司・椅子取り・エレベーター・溶岩のフレーム受信処理を実行した。時刻の巻き戻り、古い状態による位置の上書き、移動中の不要な画面全体の再生成がないことを確認した。
- エレベーターの本番描画関数、壁よけの移動予測、切断後の時計情報のリセット、別プレイヤーのフレームの拒否、既存Build613サーバーの時計応答との互換を確認した。
- 船、スター、ボス、協力ギミック、ゲーム選択、キャッシュ更新の回帰テストを実施した。

テストはNode上で実行した。受信処理のVMテストでは、その処理で使用しない表示素材・音声・ウォレットなどをスタブ化した。iPhone Safari実機、公開中サーバーへ複数端末を接続したプレイ、描画FPSは未確認。
