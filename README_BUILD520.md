# Build520 / v3.1.199

**Build519適用済みの完全なプロジェクトへ重ねる差分ZIP。単独では動作しない。**

ブロック落としサバイバルの操作・脱落判定・画面表示を更新する。他のミニゲームのルール、〇×問題集とAI、所持魔物、戦闘、育成、セーブ形式は変更しない。

## 変更内容

- スティックを廃止し、左・右・超ジャンプ・通常ジャンプの大きな四角ボタンに変更。面全体に当たり判定を持つ。左右は長押し、左右間のスライド、２本指の同時操作に対応する。左右を同時に押した場合は後から押した側を優先し、その指を離すと先の指の操作に戻る。
- ダッシュを廃止する。通常ジャンプは従来の２段。超ジャンプは５段、初回から使用可能、発動から15秒後に再使用可能。発動は地面・ブロック・仲間の頭から行う。空中での追加ジャンプはできない。着地直前160msの入力は着地時に受け付ける。
- 超ジャンプは足元の紋章、上昇する光、効果音で表現する。ボタンに再使用までの秒数と蓄積ゲージを表示し、使用可能になったら光る。AIも同じ高さ・待機時間で使用する。
- 固定されたブロックで出口への経路が完全に閉じた本人を、その物理更新で脱落させる。開放された場所の仲間は続行できる。全員脱落なら直ちに勝敗を決め、既存の5.4秒の決着演出へ移る。落下途中のブロックだけで封鎖を確定しない。単に足場が高い、超ジャンプの再使用待ち、といった状態を完全封鎖扱いにしない。
- 標準の盤面は画面左右12pxずつを残して全幅表示する。ブロックの正方形は保ち、逃げる側は上方が広く見える追従カメラにする。落とす側は生存者と着地点の高さを追う。両側とも小さな全体図と「全体を見る／近くを見る」で状況を確認できる。画面外から迫るブロックは該当列に警告する。
- 深緑の城壁から上部の空へつながる専用背景を追加。背景画像は768×1344pxのWebP１枚、148,888 bytes。背景と着地済みブロックをキャッシュし、カメラ移動だけで作り直さない。DPR上限は1.5。非表示時は描画停止。画面更新用のRAFは従来どおり１本。
- キーボードは左右/A/Dで移動、上/W/スペースで通常ジャンプ、Shiftで超ジャンプ。落とす側のキーボード操作は継続する。
- 決着演出中のタイマーは終了時の値を表示する。

## 適用手順

1. 動作中の完全なBuild519のファイルをバックアップし、ZIPをプロジェクトのルートへ上書きする。ZIP内の `src`、`assets`、`online-server` はそれぞれ既存の同名フォルダへ重ねる。
2. フロント側の `index.html`、`src`、`assets`、Build520のオフライン関連ファイルを公開環境へ反映する。
3. **オンラインサーバー側にも `online-server/src` と、同階層にある共有のルート `src` を反映し、Nodeサーバーを再起動する。** サーバーはルート `src/tower` の物理とAIを直接読むため、`online-server` フォルダだけでは不足する。
4. 全員がページを再読み込みする。表示版は v3.1.199。塔ゲームの通信バージョンを3に上げており、旧版のダッシュ入力は受け付けない。新旧混在では更新を案内する。
5. 反映後は実機で左右長押し＋ジャンプの同時操作、超ジャンプの15秒表示、全体表示切り替えを確認する。

開始済みの旧対戦はサーバー再開時の進行処理で新ルールへ一度だけ移行し、超ジャンプを使用可能にする。Build520の待機時間は保存・復元される。対戦中の更新は避け、参加者全員が更新してから開始することを推奨する。

## 検証

150テスト成功、失敗0。AI100試合すべて終了、逃げる側15勝・落とす側85勝。同じ100シードの前版の記録は7勝・93勝である。これはAIシミュレーションの結果であり、人間同士の勝率・操作感の実測値ではない。

追加18テストでは５段の高さ、15秒、空中での不発、着地直前入力、頭からの発動、天井との衝突、個別封鎖、全員封鎖、保留すべき状態、保存復元、通信バージョンと重複入力、AIの超ジャンプ、複数画面サイズ、２本指とスライド、描画キャッシュを確認した。

**実ブラウザー・実iPhone・実際のマルチタッチ・実WebSocket回線での再確認は未実施。** DOM入力テストは検証用ノード、画像検証は製品Canvas描画コードをネイティブCanvasへ出力したものである。

引き継いだ作業コピーには `species.js`、`endgameCharacters.js`、`MonsterVisual.js` がない。既存テストではこの３つだけをメモリー内のfixtureで補っている。製品用の代用品は作成していない。必ず動作中の完全な元プロジェクトへ適用する。

**公開先への適用・オンラインサーバーの再起動は実施していない。**
